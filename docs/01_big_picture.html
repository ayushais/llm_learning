Big picture

How an LLM works: the 30,000-foot view

A large language model is a function that reads a sequence of tokens and outputs a probability distribution over the next token. Everything else (chat, code, reasoning) is built by calling that function in a loop and by training it well. This module walks through the whole pipeline once, so the later modules have a map to hang details on.

Code companion: notebooks/01_big_picture.ipynb takes apart the real GPT-2 (124M) on your CPU: tokens, next-token probabilities, a hand-written generation loop, perplexity, parameter accounting, and attention maps.

1. The one-sentence model

Given tokens t1…tn, the model computes P(tn+1 | t1…tn). By the chain rule of probability, a model of this conditional is equivalent to a model of whole sequences:

P(t1…tn) = P(t1) · P(t2|t1) · … · P(tn|t1…tn-1)

This is the autoregressive language-modelling idea that goes back to n-gram models and the neural version by Bengio et al. (2003). The modern change is mostly the network that computes the conditional, and its scale.

2. The pipeline

Step by step, with GPT-2 small as the example

StageWhat happensShape (batch 1, T tokens)
TokenizeByte-pair encoding splits text into subword pieces from a 50,257-entry vocabulary (Sennrich et al. 2016)(T)
EmbedEach id indexes a learned row of a 50,257×768 table. GPT-2 adds a learned vector per position(T, 768)
AttentionEach token mixes in information from earlier tokens, weighted by learned relevance(T, 768)
MLPPer-token two-layer network, 768→3072→768(T, 768)
UnembedMultiply by the transposed embedding table to score every vocabulary entry(T, 50257)
SampleSoftmax the last row, pick a token, append, repeatone id

The attention and MLP blocks keep the shape the same, and each adds its output to a running vector called the residual stream. A useful mental model from Elhage et al. (2021): the residual stream is a shared workspace, and every layer reads from it and writes small updates back.

3. The two components

Self-attention: moving information between positions

Each token produces a query, a key and a value vector. A token's output is a weighted average of the values of the tokens it attends to, where the weights come from softmax(query·key / √d). A causal mask stops any position from reading future tokens, which is what lets one forward pass train on every position at once. Introduced in Vaswani et al. 2017. Module 4 builds it from scratch.

MLP: per-token computation and storage

The MLP processes each position independently. It holds about two thirds of the block parameters (8d² of 12d² per block) and is thought to store much of the model's factual knowledge (Geva et al. 2021). Modern models swap the activation for SwiGLU (module 5).

Where GPT-2's 124M parameters are (measured in the notebook): MLP 56.7M, token embeddings 38.6M, attention 28.3M, position embeddings 0.8M, norms ~0. The output layer reuses the token embedding matrix (weight tying), so it costs nothing extra.

4. How the model is trained

Stage 1: pretraining

Train on a huge text corpus to minimise cross-entropy: the average of −log P(actual next token). Perplexity is exp(loss), roughly the number of tokens the model is "choosing between" on average. In the notebook, GPT-2 has perplexity ~160 on "The quick brown fox…" but ~10,000 on the same words shuffled. No labels are needed because the text supplies its own targets (self-supervision). This stage costs nearly all the compute.

Two empirical findings shape this stage. Kaplan et al. (2020) showed loss falls as a smooth power law in parameters, data and compute. Hoffmann et al. (2022, "Chinchilla") found that most large models were undertrained: for a fixed compute budget, parameters and training tokens should grow together, roughly 20 tokens per parameter. Module 6 covers both.

Stage 2: supervised fine-tuning (SFT)

A pretrained model continues text; it doesn't follow instructions. Training on curated (instruction, good response) pairs teaches the format of being an assistant. InstructGPT (Ouyang et al. 2022) showed that a 1.3B model tuned this way was preferred by humans over the 175B base GPT-3.

Stage 3: preference tuning and reinforcement learning

Humans (or models) rank responses; the model is pushed toward preferred ones, via RLHF with a learned reward model (InstructGPT) or directly via DPO (Rafailov et al. 2023). More recent work uses reinforcement learning against verifiable rewards (math answers, unit tests) to improve reasoning. Module 12 and 13.

5. Generation

At inference time the model is run in a loop: forward pass, pick a token from the distribution, append, repeat. The choice rule matters a lot:

  • Greedy (always the top token): deterministic, but repetitive and bland.
  • Temperature: divide logits by T before softmax. T<1 sharpens, T>1 flattens.
  • Top-k / top-p: sample only from the most likely tokens (Holtzman et al. 2020 showed pure sampling and beam search both produce degenerate text).

Naively re-running the whole prefix for each new token wastes work; the KV cache (module 8) fixes that. Try exercise 4 in the notebook to see the cost.

6. Common misconceptions

  • "It just looks up similar text." The weights are far smaller than the training data. The model must compress patterns, which pushes it toward generalisation. (It can still memorise rare, duplicated passages.)
  • "It only predicts one token, so it can't plan." Each token is chosen after computation spanning all layers and positions, and intermediate states are reused later through attention. Whether and how models plan ahead is an active interpretability question. Generating reasoning text before answering also gives the model more computation per answer (module 13).
  • "Words are the unit." Tokens are subword fragments. This is why models struggle with letter counting, arithmetic digits and rare strings.
  • "Chat is a different kind of model." A chat model is the same architecture, with the conversation flattened into one token sequence using special tokens.
