The core operation of the transformer

Self-attention step by step

Module 3 ended with two kinds of language model. The bigram table looks at one previous character. The Bengio-style network looks at a fixed window of n previous characters, with a separate set of weights for each slot of the window, and stops improving at around n=4 on Shakespeare. Both have the same limitation: which earlier token matters is decided by position, not by content. In the sentence “The keys that she lost yesterday were on the table”, the verb must agree with “keys”, however many words sit in between. Self-attention is the operation that lets each token look back over the whole context and decide, from content, where to read from. It is the part of the transformer that moves information between positions; everything else in the model works on each position separately.

1. From averaging to attention

Start with the crudest way to let a token use its past: replace its vector by the average of the vectors of all tokens up to and including itself. Written as a matrix product, with X the T×d matrix of token vectors (one row per position), the averaging is a lower-triangular matrix A whose row i holds 1/i in the first i entries and 0 after:

out = A · X

The zeros above the diagonal are what stops a token from seeing the future. This is a fixed, content-blind mixing rule. Attention keeps the structure (out = A · values, with A lower-triangular and every row summing to 1) but computes the entries of A from the tokens themselves, so that a token can put most of its weight on the few earlier tokens that are relevant to it. The idea of a learned, content-dependent weighted average over a sequence appeared in machine translation as Bahdanau, Cho & Bengio 2014 (a decoder choosing which source words to look at) and Luong et al. 2015 (a dot-product score). Vaswani et al. 2017 removed the recurrent network around it and kept only attention, hence “Attention is all you need”. “Self” means that queries, keys and values all come from the same sequence.

2. Queries, keys and values

Each token vector xi (a row of X, d numbers) is projected three ways with learned matrices Wq, Wk (d×dk) and Wv (d×dv):

qi = xi Wq,   ki = xi Wk,   vi = xi Wv

  • The query qi says what token i is looking for.
  • The key kj says what token j offers to be found by.
  • The value vj is what token j hands over if it is found.

Key and value are different vectors on purpose: what makes a token match and what it contributes are different questions. The score of token i for token j is a dot product, large when query and key point the same way. The weights are a softmax of the scores over j, and the output is the weighted average of the values:

Attention(Q, K, V) = softmax( Q KT / √dk + M ) · V

Here Q, K, V are the T×dk (or dv) matrices that stack all qi, ki, vi; Q KT is the T×T table of all pairwise scores; the softmax is taken along each row; and M is the causal mask: 0 on and below the diagonal, −∞ above it, so that those weights come out exactly 0. The √dk is explained in the next section. A dictionary lookup is the right picture if you make it soft: instead of returning the one value whose key equals the query, you return a blend of all values, weighted by how well each key matches.

A worked example

Figure 2 runs the formula on four tokens with two-dimensional keys, so you can check it with a calculator. Read row q3: it scores the three tokens it may see (k1, k2, k3) as 1, 2, 2, divides by √2, and after the softmax puts about 0.20, 0.40, 0.40 of its weight on them. Its output is that mix of v1, v2, v3. Row q1 can only see itself, so its weight is 1.00. That last point generalises: the first token can only ever copy its own value, which matters in Section 6.

3. Why divide by √dk

Vaswani et al. note the reason in one sentence: if the components of q and k are independent with mean 0 and variance 1, the dot product q·k has mean 0 and variance dk, because it is a sum of dk independent products each of variance 1. So the scores get bigger as the head dimension grows, and a softmax of large numbers is almost a one-hot vector: one key takes nearly all the weight and the gradient through the others is close to zero. Dividing by √dk restores unit variance, so the softmax stays equally soft for any head size and one learning rate works across sizes. Figure 3 checks this by simulation; the same effect is reproduced in the notebook with and without the scale.

The assumption (unit variance, independent components) holds at initialisation, not necessarily after training; trained models can and do learn very sharp attention where they need it. The scale just makes the starting point well-behaved.

4. The causal mask and parallel training

A language model must predict token t+1 from tokens up to t only. With the causal mask, row i of the weight matrix is zero beyond column i, so the output at position i is a function of tokens 1..i alone. The consequence is the reason transformers train fast: one forward pass over a sequence of T tokens gives T next-token predictions and T loss terms at once, each seeing exactly its own prefix. (A recurrent network has to run T sequential steps for the same thing.) At generation time there is no future to hide; the mask only matters during training and prompt processing.

Implementation detail: the mask is added to the scores before the softmax, as −∞. Multiplying the weights by 0 afterwards would leave rows that no longer sum to 1.

One more property to keep in mind: attention by itself has no notion of order. If you permute the input tokens, the outputs are permuted the same way and nothing else changes (“permutation equivariance”); the mask is the only thing that treats earlier and later differently, and it is not enough to tell “dog bites man” from “man bites dog” for the tokens in the middle. Order has to be injected through positional information: learned position vectors added to the embeddings (used in the experiments below) or rotations of q and k (RoPE, Module 7).

5. Multi-head attention

One attention head produces one weighted average per token, i.e. it can attend to one “kind” of thing at a time. Multi-head attention runs h heads in parallel, each with its own Wq, Wk, Wv, and then concatenates their outputs and mixes them with an output matrix Wo:

MultiHead(X) = concat(head1, …, headh) · Wo

The standard choice is dk = dv = d/h: the model dimension is split among the heads, not multiplied. GPT-2 small has d=768 and h=12 heads of 64 dimensions each (the original transformer base model used d=512, h=8, dk=64). Consequences worth knowing by heart:

  • Parameters do not depend on h. Wq, Wk, Wv, Wo together are 4d² weights (plus biases). For GPT-2 small that is 2,362,368 per layer, about 28M over 12 layers. Most implementations fuse the three projections into one d×3d matrix (GPT-2 calls it c_attn) and cut the result into heads with a reshape.
  • Compute and memory are quadratic in T. Every head forms a T×T score table: at T=1,024 and 12 heads that is 12.6 million numbers per layer per sequence, and it grows four-fold when the context doubles. This is the problem that the KV cache, grouped-query attention and FlashAttention attack (Module 8).
  • Wo is not decoration. The concatenation puts each head's output in its own slice of the vector; Wo decides how those slices are written back into the shared residual stream that the rest of the network reads (Module 5).
  • More heads is a design choice, not a free win: Michel et al. 2019 found that many heads of trained translation and BERT models can be removed at test time with small loss.

6. What the heads of a real model do

The notebook rebuilds GPT-2 small's attention from its raw weight matrices, using only the function of Section 2, and compares with the Hugging Face model. Result (computed on 12 windows of real text): layer 5: largest difference in any attention weight 6.0e-07; largest difference in the block output 2.3e-05. So the from-scratch code is the same computation, to floating-point precision. With that confidence, we can look at the 144 attention maps (12 layers × 12 heads) of GPT-2 and see what they do. Figure 4 shows four, chosen automatically by a score rather than by eye.

Previous-token and induction heads

The first head type is the plain one: attend to the token right before me. It looks trivial, but it copies each token's identity one position forward, which is the first half of the next trick. An induction head completes patterns of the form “A B … A → B”: when the current token A appeared earlier in the context followed by B, it attends to B and its output pushes the model to predict B again. In Figure 4 the sentence repeats “The cat sat”; at the second “cat” the induction head puts 79% of its weight on “sat”, the word that followed the earlier “cat”, and at the third “cat” 47%. Elsewhere it mostly rests on the first token. To find induction heads without eyeballing, we use the test of Olsson et al. 2022: feed a sequence of random tokens repeated twice and measure how much weight a head puts, at each position of the second copy, on the token that followed the same token in the first copy. In GPT-2 small the best head in each of layers 5, 6 and 7 scores above 0.9 on this test, while the best head in each of layers 0–4 scores below 0.02. Olsson et al. argue that these heads are a major source of in-context learning (copying and completing patterns from the prompt); that argument is evidence, not a closed case, and is easiest to make for small models.

The first token as a parking place

Many heads in the middle of the network put most of their weight on the very first token (Figure 5), whatever it is. The softmax forces every row to sum to 1, so a head that has nothing useful to read still has to put its weight somewhere; the first token, which in a causal model is visible to every later position, becomes the default dump, and its value vector is learned to be harmless. Xiao et al. 2023 call this an attention sink and exploit it to make streaming generation work (always keeping the first few tokens in the cache). Practical lesson: high attention weight does not mean “important information is here”.

A caution about reading attention maps

The heatmaps are tempting as explanations (“the model looked at keys when it chose were”), but a weight only says how much of a token's value vector enters the average. A token with a tiny-norm value can have high weight and no influence, as with the sink above, and the output of a head is further transformed by Wo and every later layer. Jain & Wallace 2019 showed that attention weights can often be changed substantially without changing predictions, and Wiegreffe & Pinter 2019 replied that this depends on what you mean by explanation; the fair summary is that attention weights are a useful diagnostic and not a proof of what the model relied on. Heads are also not always cleanly specialised: Clark et al. 2019 found some BERT heads that line up with syntax, and many that do not fit a tidy description.

7. A tiny model that learns to attend

Back to the Module 3 task: next-character prediction on TinyShakespeare, same train/held-out split. The model is as small as it can be: character embedding plus a learned position embedding (d=64, context 64), then L causal attention layers each followed by a residual add, then a linear layer to the 65 characters. No MLP, no normalisation, no dropout; those are Module 5. All trained with Adam for 4,000 steps (a few minutes on a CPU).

Three things to read off. (1) Attention works: a single layer with four heads is already far better than the bigram (about 2.49 nats). (2) Four heads beat one head with the same number of parameters, which is the practical argument for splitting the dimension. (3) The best attention-only model here is roughly as good as the 8-character neural LM and the count-based 4-gram of Module 3, not better. At this scale and training length that is expected: those baselines fully memorise short contexts, while an attention-only model has no per-position nonlinearity (no MLP) and spends capacity on learning where to look. The advantage of attention shows when the useful context is long and variable, and we have not tested that. 8. Common misconceptions

  • “Attention weights show why the model answered as it did.” They show where each head read from, weighted by nothing about how much that value matters downstream. See the caution in Section 6.
  • “Q, K and V are the input split three ways.” They are three different learned linear maps of the same input. The key and the value of a token are different vectors.
  • “More heads means more parameters / more power.” With d/h-dimensional heads the parameter count is the same; heads trade width per head for the number of distinct attention patterns.
  • “Attention knows the word order.” Alone it does not; position must be added (Module 7).
  • “The causal mask only matters for inference.” It is the opposite: it is essential in training, where it stops position i from reading the answer at i+1. At generation time there is nothing to mask.
  • “Attention is O(T) because each token reads a few others.” Dense attention scores every pair: O(T²) in compute and, naively, in memory.
