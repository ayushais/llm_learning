Embeddings and a first language model

Embeddings and a bigram baseline

Module 2 ended with a sequence of integers. A neural network cannot do arithmetic on token id 3797 in any useful way, because the number 3797 has no geometry: id 3796 is not “nearby” in meaning. The first layer of every language model therefore replaces each id by a learned vector. This module shows what that layer is, builds the simplest possible language model out of it (one that looks at a single previous character), and then follows the 2003 paper of Bengio et al. that turned the idea into a neural language model, the direct ancestor of GPT.

1. What an embedding layer is

Let the vocabulary have V tokens and let E be a matrix with V rows and d columns. The embedding of token x is just row x of E:

e = E[x]   =   onehot(x)T · E

The right-hand form says the same thing as a matrix product with a one-hot vector (a vector of V zeros with a single 1 at position x). Nobody computes it that way, because multiplying by a one-hot vector is an expensive way of selecting a row; nn.Embedding just indexes. But the one-hot view tells you what the layer is: a linear layer with no bias whose input is a one-hot vector, and so everything you know about linear layers carries over.

Gradients are sparse. Since only the selected rows take part in the forward pass, the gradient of the loss with respect to E is zero everywhere except in the rows of the tokens that appeared in the batch. A token you never see in a batch gets no update at all. This is also why rare tokens (and the glitch tokens of module 2) end up with poorly trained embeddings.

The numbers are just parameters. Nothing about the d columns is designed; the values start random (the Hugging Face GPT-2 implementation draws them from a normal distribution with standard deviation 0.02, its initializer_range) and are shaped entirely by the training loss. The table costs V×d parameters. For GPT-2 small that is 50,257 × 768 = 38,597,376, about 31% of the model's 124M parameters.

What is d? It is the width of the model, the size of the vector that flows through every transformer layer (768 for GPT-2 small). Tokens enter as points in a d-dimensional space and every later layer reads and rewrites vectors in that same space.

2. Scoring a language model: cross-entropy and perplexity

A language model assigns a probability to the next token given the previous ones. We train it by maximum likelihood, which means minimising the average negative log-probability of the true next token:

L = −(1/N) ∑t log P(xt | x1, …, xt−1)   (nats per token, natural log)

Two reference points make the numbers readable. A model that knows nothing and guesses uniformly assigns 1/V to everything and scores L = ln V; with the 65 characters of Shakespeare that is ln 65 = 4.174. And perplexity = exp(L) is the “effective number of equally likely choices” the model is hesitating between, so the uniform guess has perplexity 65 by construction. Module 1 introduced perplexity; here we will be able to watch it fall as the model gets to use more context. (All losses in this module are on characters, so they are not comparable to GPT-2's per-token numbers.)

Intuition: the loss is surprise

For one position, the loss is −ln p, where p is the probability the model gave to the token that actually came next. Read it as the model’s surprise at what happened:

p given to the true token10.50.10.010.0001
loss −ln p (nats)00.692.304.619.21

A confident correct prediction costs almost nothing; an event the model thought nearly impossible costs a lot, and the cost grows without bound as p approaches 0. Three reasons it is the right quantity rather than, say, 1 − p:

  • It punishes confident mistakes. Falling from p=0.5 to p=0.01 costs 0.69 → 4.61, whereas 1 − p would only change from 0.5 to 0.99. A model that says “I am sure it is not this” and is wrong is penalised heavily.
  • Logs turn products into sums. The probability of a text is the product p(x1)·p(x2|x1)·p(x3|x1,x2)…, a number that underflows almost at once. Its log is a sum of per-token terms, so the loss is a plain average over positions.
  • It is maximum likelihood. Minimising the average −ln p is the same as maximising the probability the model assigns to the training text.

Everything below uses the same data as module 2: TinyShakespeare (a single text file of Shakespeare’s plays), the first 90% for training and the last 10% held out. Characters rather than BPE tokens, so that the vocabulary is a small 65 and whole tables fit on a page.

3. The bigram baseline

The smallest useful language model predicts the next token from only the previous one. Give each previous token its own row of V numbers, the logits for what comes next, and apply a softmax:

P(next = j | previous = i) = softmax(B[i])j,   B a V×V table

This is an embedding layer whose “embedding” is already the output: the lookup returns the logits directly. It has V² parameters, 4,225 here.

Two ways to fit it, one answer

Counting. The maximum-likelihood solution has a closed form. Count how often each character j follows each character i, and divide each row by its total. Figure 3 shows that table for the 30 most frequent characters. It encodes real English-like structure: after a t comes an h 34% of the time and a space 25%; after a full stop comes a newline 84% of the time and a space only 15%; after a newline comes another newline 18% of the time (a blank line) and a capital letter 77% of the time.

Gradient descent. Alternatively, treat B as ordinary parameters, start at zero (a uniform guess, loss ln 65), and minimise the cross-entropy with Adam. For one row, the gradient of the loss is the model’s predicted distribution minus the empirical distribution of what actually followed, so it vanishes exactly when the softmax of the row equals the normalised counts. Gradient descent is therefore walking towards the counting solution, and Figure 4 shows it getting there.

This equivalence is worth holding on to: training a language model by gradient descent is a way of estimating the conditional probabilities from data. Counting does it exactly for a table; for larger models, where no table fits, gradient descent is the only practical estimator.

How good is it?

On the held-out text the bigram model reaches a loss of 2.48 nats per character (perplexity about 12.0; the counted table needs a little smoothing so that pairs unseen in training do not get probability zero, and gradient descent gives 2.49). A model that ignores context entirely and only knows how common each character is (the unigram model) scores 3.35 (perplexity 28.4), and the uniform guess scores 4.17 (65). So one character of context is worth a lot already. But the samples it generates show what is missing:

The only input is the prompt, a single newline character. Sampling repeats this loop 240 times:

  1. Take the last character so far (at first, the newline).
  2. Look up its row of the table: a probability for each possible next character.
  3. Draw one character at random from that row, so a character with probability 0.3 is picked about 30% of the time.
  4. Append it to the text, and make it the new last character.

The seed is fixed, so the sample is reproducible; another seed gives a different but equally garbled one. Each step looks only at the previous character, which is why every pair is plausible while whole words are not.

(Real output: 240 characters sampled after a newline prompt, leading blank lines trimmed.) Spaces, newlines, capitals and punctuation turn up in plausible places and common pairs like th and er appear, but there are almost no words: a model that sees only the previous character cannot know which word it is in. To do better it needs more context. And here counting hits a wall.

4. The curse of dimensionality and Bengio’s idea

The obvious extension is an n-gram table: condition on the previous n characters. The number of contexts is Vn, so the table has Vn+1 entries, and it grows exponentially. For 65 characters, n=4 already means 1.16 billion cells, while the training text has about one million characters. Most contexts you will meet at test time have never been seen in training, and the table says nothing about them. The table below measures this on our data.

Bengio, Ducharme, Vincent and Jauvin (2003) named this problem and proposed escaping it by learning a distributed representation of each word and using it to predict the next word. Their model is exactly the pipeline of Figure 2: look each context token up in a shared embedding table, concatenate the vectors, pass them through a hidden layer, and apply a softmax over the vocabulary. The embeddings and the prediction function are trained together by backpropagation on the next-word loss.

Why does this help? Because the model sees a vector, not an identity. If the embeddings of a and e end up close, then whatever the model learned about the context th-a transfers to the never-seen th-e: the network is a smooth function of the embeddings, so similar inputs get similar predictions. The number of parameters also grows only linearly with the context length (each extra context token adds d×h weights to the first layer), instead of exponentially: V·d + n·d·h + h + h·V + V in total, which is 50,769 for our n=8 model.

What the experiment shows (and what it does not)

  • The count table overfits fast. Its training loss falls steadily with n (the dashed blue line) while the held-out loss turns around after n=4 and climbs to 2.34 at n=6, worse than a bigram. Smoothing keeps it finite but cannot replace missing statistics.
  • The neural model does not collapse. From n=4 to n=8 its held-out loss stays between 1.79 and 1.81, because adding a context position adds a few weights instead of multiplying the table size.
  • It does not beat the best count model here. At n=3 and n=4 the plain count model is better (1.75 vs 1.80 at n=4). Our neural model is small, trained for a single pass, and not tuned, so this is not a statement about what neural models can do; it is a reminder that on a million characters with short contexts, counting is a strong baseline. The advantage of the neural model is that it keeps working as context grows, which is the direction every later module pushes in. (Bengio et al. report their model beating smoothed n-grams on their word-level data; we do not reproduce their numbers.)
  • Neither can use long context well. A fixed window with one weight block per position cannot use a context longer than it was built for, and spends parameters on every position whether or not it matters. Attention (module 4) removes both limits: the same weights are used at every position and the model decides which earlier tokens to look at.

5. What the embeddings contain: GPT-2’s table

GPT-2’s wte is the same object as our C, scaled up (50,257 tokens, 768 dimensions) and trained as part of a deep transformer. Its rows were never told what a country or a weekday is, yet cosine similarity between rows (the dot product of the unit-length vectors) recovers a lot of structure. Analogies: real, but weaker than the folklore

Mikolov et al. (2013; Mikolov, Yih & Zweig 2013) observed that in word2vec embeddings, differences between vectors encode relations: king − man + woman lands near queen. We can test this on a modern model’s input embeddings. The nearest rows to the computed vector (excluding the three query tokens) are:

QueryClosest rows
king − man + woman␣queen, ␣princess, ␣Queen, ␣kings, Queen
Paris − France + ItalyParis, ␣Milan, ␣Italian, Italy, ␣Rome

Three work (queen, swimming, Tokyo) and one fails: for Paris − France + Italy the nearest row is Paris itself, and Rome only appears fifth, because the answer vector is still closest to the token we started from. So the linear-offset structure is real but approximate, and checking it needs care (the standard evaluation excludes the query words, as done here). Treat embedding geometry as evidence of what the layer learned, not a guarantee.

Two cautions about the geometry

  • Cosine similarity is not absolute. Two random rows of GPT-2’s table have a mean cosine similarity of 0.27, not 0. The rows share a large common component: the mean of all rows has norm 2.05, against an average row norm of 3.96. So “0.5” is not a halfway-similar score; only comparisons within the same table are meaningful.
  • An embedding row is context-free. bank has one row whether it is a river bank or a financial one. The transformer layers (modules 4 and 5) are what turn this static input vector into a context-dependent representation. What you see in wte is the model’s starting point for a token, not its final understanding of it.

6. The output side: weight tying

The last step of a language model turns the final d-dimensional hidden vector h into V logits with another V×d matrix, the unembedding U: logiti = h · U[i]. Look at that expression: token i’s score is the dot product of the hidden state with row i, which is the same kind of object as the input embedding row i: “a vector describing token i”. Press and Wolf (2016) proposed using one matrix for both. GPT-2 does this: in the Hugging Face model, lm_head.weight and transformer.wte.weight are the same tensor (checked: they share storage). Tying saves V×d parameters (38.6M for GPT-2 small) and means one matrix has to serve both as the way a token is read and as the way it is predicted. Several large model families (Llama, for example) do not tie them; at large d the saving is a smaller fraction of the total, and untied matrices give the model more freedom.

Seen this way, the bigram model of section 3 is the degenerate case with no layers in between: the “hidden vector” is the one-hot previous token, and U is the table B. A transformer is the same read-out with an enormously richer way of computing h.

7. Common misconceptions

  • “Embeddings come from word2vec/GloVe.” Modern LLMs usually learn their embedding table from scratch, jointly with the rest of the model, on the next-token loss. There is no separate pretraining step for it.
  • “Each embedding dimension means something.” Individual coordinates are not interpretable by default; what carries meaning is mostly directions in the space and the relations between rows.
  • “A bigram model is a toy with no use.” It is the baseline every model must beat, and a sanity check: a model that is no better than the bigram table has learned nothing about context.
  • “Neural models always beat counting.” Not at small scale and short context, as Figure 5 shows. They win by scaling to contexts and datasets where the count table cannot exist.
  • “Similar embeddings mean the same meaning.” happy and unhappy are near neighbours in Section 5. The geometry reflects how tokens are used, which includes being used in the same places for opposite reasons.
