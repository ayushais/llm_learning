From one attention layer to a deep network

The transformer block: residuals, RMSNorm, SwiGLU

Module 4 ended with attention-only models: embeddings, one or two attention layers with a residual add, a linear head. They beat the bigram but stalled near the count-based 4-gram, for two reasons. First, attention only moves information between positions; a weighted average of value vectors followed by a linear map is still close to linear in what it reads, so the model has almost no place to compute on what it gathered. Second, you cannot simply stack many such layers: deep plain networks are hard to train. A transformer block fixes both with three ingredients that are each a few lines of code: a feed-forward network (FFN) applied to every position separately, residual connections around both sublayers, and normalisation in front of each sublayer. This module takes them one at a time, then looks at what they do inside GPT-2 and in tiny models you can train on a laptop. Modern models (Llama and most open models since) use the same skeleton with two swaps: LayerNorm becomes RMSNorm and the GELU MLP becomes SwiGLU.

Code companion: notebooks/05_transformer_block.ipynb writes LayerNorm, RMSNorm, the GELU MLP and SwiGLU from scratch and checks them against PyTorch and Hugging Face, rebuilds a GPT-2 block from its raw weights, looks inside GPT-2's residual stream, and trains 12-block and 2-block character models with and without each ingredient. 1. The block in two lines

Write x for the T×d matrix of token vectors entering a block. The block used by GPT-2 and by essentially every large decoder since is the pre-norm block:

h = x + Attn( Norm(x) )
out = h + FFN( Norm(h) )

Attn is the causal multi-head attention of Module 4. FFN is a small two-layer network applied to each position on its own (the same weights at every position, no mixing between positions). Norm rescales each token vector (Section 3). The “x +” is the residual connection (Section 2). A model is an embedding, N such blocks, one more Norm, and the unembedding. The original transformer of Vaswani et al. 2017 put the norm after the add instead, out = Norm(x + f(x)), the post-norm block. Figure 1 shows both. The difference looks cosmetic and is not: Section 3 shows a 12-block post-norm model that cannot train at a learning rate where the pre-norm model trains fine.

A useful way to read the pre-norm picture, from Elhage et al. 2021: the vertical line is a residual stream, a d-dimensional vector per token that runs from the embedding to the unembedding. Every sublayer reads from the stream (through its norm and input projections) and adds its output back into it. Nothing is ever overwritten; a later layer sees the sum of everything earlier layers wrote. Attention is the only sublayer that moves information between positions; the FFN works within one position. The split of labour of Module 4 (“attention decides where to read”) now has a partner: “the FFN decides what to do with it”.

2. Residual connections

Residual connections come from image recognition: He et al. 2015 observed that adding layers to a plain deep convolutional network made even its training error worse, an optimisation failure rather than overfitting, and fixed it by letting each block learn a correction f(x) to its input instead of a whole new representation: y = x + f(x). The calculus is one line. The Jacobian of a residual block is

∂y/∂x = I + ∂f/∂x

so the gradient that reaches layer 1 from layer N is a product of N factors (I + small), which contains the identity path: the gradient from the loss arrives at every layer directly, plus corrections. In a plain stack it is a product of N Jacobians ∂f/∂x, which can shrink or blow up geometrically with depth. He et al. 2016 showed that the cleanest version keeps the skip path a pure identity, with nothing (no norm, no activation) on it; that is exactly what the pre-norm block does. Veit et al. 2016 add a second view: unrolling y = x + f(x) over N blocks gives a sum over 2N paths of different lengths, and a trained residual network behaves much like an ensemble of its relatively short paths.

Figure 2 measures this on a 12-block character model (d=64, the code of the notebook), at initialisation. Left: in the pre-norm model the gradient reaching each block is about the same size from bottom to top. Remove the “x +” and keep everything else, and the gradients are not small at all, they are larger; yet training (Figure 3) stalls at 3.31 nats, which is exactly the entropy of the character frequencies: the model predicts common characters and uses no context. The right panel shows why. Without the skip path, the vectors of different positions become more and more alike with every block, until after about six blocks every position carries the same vector (cosine similarity 1). Attention averages vectors, and averaging repeatedly collapses them toward their mean; Dong, Cordonnier & Loukas 2021 prove that pure self-attention loses rank doubly exponentially with depth and that skip connections (and, to a lesser extent, MLPs) prevent it. A model whose positions are indistinguishable can only predict the same distribution everywhere: the unigram. With residuals, each position keeps its own embedding in the stream and the similarity stays low.

One more detail from GPT-2 (Radford et al. 2019): since every block adds to the stream, the variance of the stream grows with the number of blocks at initialisation. GPT-2 compensates by scaling the initial weights of the layers that write into the stream (the attention output projection and the FFN's second matrix) by 1/√N, where N is the number of residual layers. Exercise 2 of the notebook tries it.

3. Normalisation: LayerNorm, where to put it, RMSNorm

LayerNorm

Ba, Kiros & Hinton 2016 normalise each token vector x (d numbers) by its own statistics:

LN(x) = (x − μ) / √(σ² + ε) ⊙ g + b,    μ = (1/d) Σi xi,   σ² = (1/d) Σi (xi − μ)²

g and b are learned per-dimension gain and bias, and ε (about 10−5) avoids dividing by zero. Unlike batch normalisation, nothing depends on other tokens or other sequences in the batch, so it behaves identically in training and generation and for any batch size. The output is invariant to adding a constant to all components of x (re-centering) and to multiplying x by a positive number (re-scaling). The second property is the important one: whatever the scale of the stream, a sublayer sees an input of fixed size.

Post-norm versus pre-norm

In the post-norm block, the norm sits on the main path, after each add, so the residual stream itself is renormalised 2N times and no identity path from the top to the bottom survives. Xiong et al. 2020 showed (with a mean-field argument and experiments) that at initialisation a post-norm transformer has large expected gradients for the parameters near the output, which makes a high learning rate unstable; this is why the original transformer needed a learning-rate warmup. With the norm moved inside the residual branch (pre-norm), the gradients are well-behaved at initialisation and the warmup could be dropped in their experiments. Pre-norm had already been used in practice: GPT-2 moved “layer normalization… to the input of each sub-block” and added a final LayerNorm after the last block, and Wang et al. 2019 and Nguyen & Salazar 2019 found it essential for training deep translation models. Liu et al. 2020 refine the story: gradient size alone does not explain post-norm instability; each post-norm layer depends heavily on its own residual branch, which amplifies small parameter updates into large output changes. They also report the other side: when post-norm does train, it often ends up better than pre-norm, because the pre-norm stream is dominated by its earlier contents and later layers change it relatively little (see Figure 5 for GPT-2).

Figure 3 reproduces the stability effect on a small scale: 12 blocks, d=64, Adam at learning rate 10−2, 400 steps, no warmup. The pre-norm model learns; the post-norm model stays at the unigram loss, and a 100-step linear warmup does not rescue it in this run. At lower learning rates both train (right panel), so the honest summary is: post-norm has a smaller range of learning rates that work, and depth makes it worse.

RMSNorm

Zhang & Sennrich 2019 hypothesise that the re-centering of LayerNorm is dispensable and that re-scaling is what matters. RMSNorm drops the mean and the bias:

RMSNorm(x) = x / √( (1/d) Σi xi² + ε ) ⊙ g

The output always has root-mean-square equal to 1 before the gain, i.e. every token vector is projected onto a sphere of radius √d. LayerNorm is the same thing applied to the centred vector x − μ, so the two coincide when the mean of x is near zero. The paper reports comparable quality to LayerNorm with 7%–64% less running time across their models, from one fewer reduction and no subtraction. Llama (Touvron et al. 2023) adopted it together with pre-norm, and most open models followed.

Two measurements put this in perspective. Speed is a property of the kernel, not just of the formula: on this laptop, at d=768 and 16k tokens, our unfused RMSNorm takes 50 ms against 98 ms for our unfused LayerNorm, about half, as the formula suggests; but PyTorch's built-in nn.LayerNorm, a fused kernel, takes 17 ms and its nn.RMSNorm 51 ms on this CPU (PyTorch 2.14). On GPUs, fused RMSNorm kernels are the norm in LLM inference engines, and that is where the saving is realised. Re-centering is not irrelevant to a model trained with it: replacing all 25 LayerNorms of a trained GPT-2 small by RMSNorm (same gain and bias, only the mean subtraction removed) raises its loss on our Shakespeare windows from 4.64 to 4.75 nats, and the top-1 prediction changes on 14% of tokens. The claim of the paper is that a model trained with RMSNorm does as well, which is what Figure 7 tests at tiny scale.

4. The feed-forward network: from GELU to SwiGLU

The FFN of the original transformer is two linear maps with a nonlinearity between them, applied at every position independently:

FFN(x) = φ( x W1 + b1 ) W2 + b2,   W1: d×4d,   W2: 4d×d

The hidden layer is four times wider than the stream, and φ was ReLU in Vaswani et al. and GELU, x·Φ(x) with Φ the standard normal CDF (Hendrycks & Gimpel 2016), in BERT and GPT-2 (GPT-2 uses a tanh approximation of it). Count parameters: the FFN has 8d², attention 4d². For GPT-2 small that is 4,722,432 against 2,362,368 per block: two thirds of the block's parameters are in the FFN, and two thirds of its matrix-multiply compute at short context. What do they store? Geva et al. 2021 read the FFN as a key-value memory: each row of W1 is a key that fires on some textual pattern in the input (they find human-interpretable patterns, shallow ones in lower layers and more semantic ones in upper layers), and the matching row of W2 is a value written into the stream, which in upper layers often promotes the tokens likely to come next.

Gated linear units

A gated linear unit (Dauphin et al. 2016) multiplies two linear projections of the same input, one of them passed through a sigmoid: GLU(x) = σ(xW) ⊙ xV. One branch decides, per hidden unit, how much of the other passes. Shazeer 2020 replaced the first FFN layer by such a gate and tried several activations in place of the sigmoid (ReLU: ReGLU, GELU: GEGLU, Swish: SwiGLU, none: bilinear), all without biases:

FFNSwiGLU(x) = ( Swish(x W) ⊙ x V ) W2,   Swish(z) = z·σ(z)

Swish (Ramachandran et al. 2017; PyTorch calls it SiLU) is a smooth ReLU, very close to GELU (Figure 4). Three matrices instead of two would add parameters, so Shazeer cut the hidden width by 2/3 to keep parameters and compute equal (in T5-base, 3072 → 2048). In his pre-training comparison on C4 after 65,536 steps, held-out log-perplexity was 1.997 for ReLU, 1.983 for GELU, 1.944 for SwiGLU and 1.942 for GEGLU (run-to-run spread about 0.005), and the GLU variants also scored better on most fine-tuning tasks. The paper is candid about the theory: “We offer no explanation as to why these architectures seem to work; we attribute their success, as all else, to divine benevolence.” PaLM (Chowdhery et al. 2022) and Llama adopted SwiGLU; Llama uses a hidden size of 2/3·4d.

A plausible intuition, not a proof: in a plain MLP each hidden unit is φ(w·x), a function of a single direction of x. In a GLU each unit is a product of two directions, a multiplicative interaction, which lets a unit respond to “feature A and feature B” with one unit instead of several.

5. Inside GPT-2

To make sure the block in this lesson is the real thing, the notebook rebuilds GPT-2 small's block 5 from our own LayerNorm, attention and MLP classes with GPT-2's weights copied in: the largest difference from the Hugging Face block output is 1.9e-05, on a stream whose entries reach 2,921. Then it tracks the residual stream through all 12 blocks on 8 windows of 256 tokens of Shakespeare (Figure 5).

Three observations, each tied to something above.

  • The stream grows and each write is a small edit. The average norm of a token vector goes from 50 after block 1 to 549 after block 12 (the embedding itself is only 4.7). Yet from block 2 to block 11 every attention and MLP sublayer adds a vector whose norm is only 0.15–0.41 of the stream's (Figure 5, right); only the first block, which builds on the bare embedding, and the last attention layer make large edits. This is the pre-norm signature that Liu et al. describe: since the stream is never renormalised, it keeps its history, and each block nudges it. The norms in front of each sublayer are what allow this: whatever the size of the stream, attention and FFN see inputs of fixed scale.
  • Massive activations. The first token's vector is not like the others: from block 3 on its norm is in the thousands (about 3,008 after block 6, against 77 for the others). Almost all of it sits in a few coordinates: after block 6, dimension 447 holds 2,899 and dimension 138 holds 800, while the median absolute entry of ordinary tokens is 1.27. Sun et al. 2024 found such “massive activations” across many LLMs, nearly constant across inputs, acting like fixed biases and concentrating attention on their token. This is the mechanism behind the attention sink of Module 4: after a norm, token 0's vector is dominated by a couple of fixed dimensions, which makes it an easy, input-independent target for keys. It also shows why a norm in front of each sublayer matters: without it, one dimension at 3,000 would swamp everything a sublayer reads.
  • The mean is small. For the ordinary tokens, |mean| is at most 0.02 of the RMS at every layer, which is the regime in which RMSNorm and LayerNorm nearly coincide.

If the stream is a running draft of the answer, we can read the draft early. The logit lens (nostalgebraist 2020) applies the final LayerNorm and the unembedding to the stream after block l, as if the model stopped there. Figure 6 shows how the next-token loss and the agreement with the final prediction evolve. For GPT-2 small the draft is hard to read until late: through block 7 the decoded loss stays near that of a uniform guess and the top-1 token matches the final one in only 9–15% of positions; agreement then climbs to 50% after block 11, and the last block alone takes the loss from 6.6 to 4.6 nats. Part of this is the lens, not the model: nothing trains early layers to be readable by the final unembedding, and later work fits a separate linear map per layer to read them better (the “tuned lens”, Belrose et al. 2023). What the figure does show is that the prediction is built up additively, and that in this small model the last blocks do a large share of the work.

6. Tiny models: what each ingredient buys

Back to next-character prediction on TinyShakespeare, scored exactly as in Module 4 (held-out windows, positions ≥ 8). All models have 2 blocks, d=64, 4 heads, context 64, and are trained for 2,000 Adam steps at learning rate 3·10−3 with cosine decay, two seeds each. Starting from the Module 4 attention-only model, we add the GELU MLP, then pre-LayerNorm (which gives the GPT-2 block), and finally swap to RMSNorm + SwiGLU at matched parameter count (the Llama block).

Read it top to bottom. The MLP is the big step: 1.94 → 1.72 nats, with the parameter count going from 45,761 to 111,937; the model now has somewhere to compute on what attention gathered, and it moves past the count-based 4-gram (1.75) that the attention-only model of Module 4 could not reach. Pre-LayerNorm does nothing for a 2-block model (1.73 vs 1.72, while the two seeds of one configuration differ by up to 0.03): normalisation buys stability at depth and at high learning rates (Figures 2 and 3), not a better 2-block model. RMSNorm + SwiGLU at the same parameter count gives the lowest loss, 1.70, 0.03 below the GPT-2 block, and both of its seeds beat both GPT-2-block seeds. That is consistent with Shazeer's result but small, from two seeds in one tiny setting; treat it as a direction, not a measurement of the gain at scale.

7. The modern block, complete

Putting the pieces together, this is the block of Llama-style models, minus rotary position embeddings (Module 7) and grouped-query attention (Module 8). It is the Block class of the notebook with norm="rms", ffn="swiglu":

class RMSNorm(nn.Module):
    def __init__(self, d, eps=1e-6):
        super().__init__()
        self.eps, self.weight = eps, nn.Parameter(torch.ones(d))
    def forward(self, x):
        ms = x.pow(2).mean(-1, keepdim=True)     # mean square
        return x * torch.rsqrt(ms + self.eps) * self.weight

class SwiGLU(nn.Module):
    def __init__(self, d, hidden):     # hidden ≈ 2/3 · 4d
        super().__init__()
        self.gate = nn.Linear(d, hidden, bias=False)
        self.up   = nn.Linear(d, hidden, bias=False)
        self.down = nn.Linear(hidden, d, bias=False)
    def forward(self, x):
        return self.down(F.silu(self.gate(x)) * self.up(x))

class Block(nn.Module):
    def __init__(self, d, h):
        super().__init__()
        self.n1, self.att = RMSNorm(d), MultiHeadAttention(d, h)
        self.n2, self.ffn = RMSNorm(d), SwiGLU(d, int(8 * d / 3))
    def forward(self, x):
        x = x + self.att(self.n1(x))     # mix positions
        return x + self.ffn(self.n2(x))  # compute per token

Variants you will meet in model cards, each a small change to these lines:

  • No biases anywhere. PaLM removed biases from all dense layers and norms, reporting better stability for large models; Llama has none either.
  • Parallel block. PaLM (following GPT-J) computes y = x + Attn(Norm(x)) + FFN(Norm(x)): both sublayers read the same input, so their input projections can be fused, which PaLM reports as about 15% faster training at large scale, with a small quality loss at 8B parameters and none at 62B.
  • Hidden size rounding. 2/3·4d is usually rounded up to a multiple of 256 or similar for hardware efficiency, so you will see odd-looking FFN widths.

8. Common misconceptions

  • “Normalisation keeps the activations of the model small.” In a pre-norm model it controls only what goes into each sublayer. The residual stream itself is never normalised and grows with depth (GPT-2 small: about elevenfold from block 1 to block 12, and token 0 reaches norms in the thousands).
  • “The residual connection is just an optimisation trick.” It is that, and it also defines the architecture's information flow: every sublayer adds to a shared stream that later sublayers read. Interpretability work on transformers is largely built on this view.
  • “Attention is where the parameters are.” In a standard block the FFN has twice as many as attention (8d² vs 4d²).
  • “SwiGLU adds parameters.” It adds a third matrix but shrinks the hidden width to 2/3 so the count stays the same. The comparison in Shazeer 2020 is at equal parameters and compute.
  • “RMSNorm is a faster LayerNorm, so it is always faster.” It does less arithmetic; whether that wins depends on the kernel. On this CPU PyTorch's fused LayerNorm beats its RMSNorm.
  • “Pre-norm is strictly better than post-norm.” It is more stable and easier to tune. Post-norm can reach better results when it trains (Liu et al. 2020), which is why stabilised post-norm variants keep being proposed.
  • “The FFN is applied to the whole sequence.” It is applied to each position separately with the same weights; only attention mixes positions.
